## 2. 已完成的业务能力

### 2.1 登录与账号

- 进入系统先显示邮箱/密码登录页。
- 新员工由超级管理员在“人员管理”中创建。
- 初始密码统一为 `123456`，首次登录必须修改。
- 忘记密码时，员工提交重置申请；超级管理员也可以直接重置员工密码。
- 管理员重置后，密码恢复为 `123456`，旧会话失效，下次登录必须改密。
- 密码使用 PBKDF2-SHA256 加盐哈希保存，不保存明文。
- 会话有效期 7 天；连续登录失败会触发临时锁定。

|---|---|---|---|

| 普通员工 | `employee@abc.local` | 仅本人创建的单据 | 新建、修改本人可编辑单据、上传附件 |

### 2.3 收付款单据

新建或修改单据时包含：

- 业务类型：收款或付款/报销
- 金额、业务事项、往来单位/人员、说明
- 资金账户：银行账户或现金账户
- 部门
- 项目（可选）
- 收入分类或支出分类
- 附件：图片、PDF、Word、Excel，单个不超过 20MB

账户、部门、项目和分类由超级管理员在“系统设置”中维护。单据列表、详情和 Excel 导出均包含这些字段。

### 2.4 审批流程

付款/报销流程：

1. 申请人提交。
2. 本部门负责人审批。
3. 财务复核。
4. 老板审批。
5. 出纳付款，流程完成。

收款流程：申请人提交后由财务确认，确认后完成。

任一审批环节均可驳回。超级管理员可以处理全部审批，也可删除单据；普通岗位不能越部门或越环节审批。

### 2.5 财务与安全功能

- 发票管理、应收应付到期日、收付款计划
- 银行流水 CSV 导入、自动对账
- 月度统计、收支分类、财务报表、Excel 导出
- 银行账户、现金账户、部门、项目、收支分类、期初余额
- 期初余额进入工作台账面结余、财务报表和月度统计
- 回收站、操作日志、手动备份、自动备份、数据恢复
- 站内消息、邮件/企业微信/钉钉 Webhook 配置
- 外部通知发送结果记录（发送中、成功、失败、返回码/错误）

## 3. 数据存放位置

### 3.1 生产环境

- 业务结构化数据保存在 Sites 项目绑定的 D1 数据库中。
- 附件和 JSON 备份文件保存在 Sites 项目绑定的 R2 存储桶中。
- `.openai/hosting.json` 只保存项目标识和逻辑绑定名，不包含数据库内容、密码或 Webhook 密钥。
- 换电脑不会导致生产数据丢失。只要继续发布到同一个 Sites `project_id`，生产 D1/R2 会沿用。

### 3.2 本地开发环境

- `pnpm dev` 使用本机项目目录下 `.wrangler/` 的本地 D1/R2 模拟数据。
- 本地数据与生产数据完全分开；换电脑后本地模拟数据默认是空的，会由初始化逻辑创建基础账号和默认参数。
- `.wrangler/`、`dist/`、`node_modules/` 不应提交到 Git，也不需要跨电脑复制。

### 3.3 备份范围

每日/手动 JSON 备份包含业务数据、人员账号及密码哈希、通知设置、通知发送记录、操作日志和回收站记录。备份不包含登录会话、登录失败记录、密码重置申请和备份清单本身。

附件备份保存附件的数据库元数据；附件二进制文件继续保留在 R2 中。恢复业务备份不会重新上传附件文件，因此不要单独清空生产 R2。

建议安装：

```bash

pnpm lint

pnpm dev
```

验收标准：

- 8 项测试全部通过。
- TypeScript 无错误。
- ESLint 无错误。
- 构建成功并生成 `dist/server/index.js`。
- 本地页面可打开，能够使用初始化账号登录并进入首次改密流程。

### 5.3 日常开发顺序

1. 开始前执行 `git pull --ff-only origin master`。
2. 修改代码。
3. 若改了 `db/schema.ts`，执行 `pnpm db:generate`，确认 `drizzle/` 新迁移已生成。
4. 执行测试、类型检查、代码检查和构建。
5. 提交并推送 GitHub。

```bash
git status

git commit -m "feat: 简要说明本次修改"
git push origin master
```

不要提交 `.env*`、`.wrangler/`、`dist/`、`node_modules/`、备份文件或真实 Webhook 地址。

## 7. 自动任务与通知

- `vite.config.ts` 中 Cron 为 `5 16 * * *`，对应北京时间每天 00:05。
- `worker.ts` 的 `scheduled()` 调用 `runDailyJobs()`。
- 每日任务使用 `daily_job_runs` 的“任务名 + 日期”唯一约束，防止同一天重复执行。
- 如果平台定时器未及时触发，用户首次进入系统时会执行补偿任务。
- 每日任务会创建自动备份，将逾期计划/发票更新为逾期，并向超级管理员、财务、老板和出纳发送站内汇总提醒。
- 仅当邮件、企业微信或钉钉 Webhook 已配置并启用时，才会真正发送外部通知并产生发送记录。

接手后的第一天应在“数据安全”中确认当天每日任务状态为“已完成”，并在“消息中心”查看通知发送记录。

## 8. 数据恢复操作

生产界面操作路径：超级管理员登录 -> 数据安全 -> 数据备份与恢复。

- “下载”：将 JSON 备份保存到电脑，适合异地留存。
- “立即备份”：创建手动备份。
- “恢复”：系统先生成“恢复前备份”，再用选定备份覆盖业务数据。
- “回收站恢复”：适合恢复单条误删记录，不必覆盖全部数据。

恢复是高风险操作。执行前应先下载最新备份，并确认要恢复的备份日期。不要删除或重建 Sites 项目，否则原 D1/R2 绑定可能丢失。

## 9. 当前自动测试覆盖

`tests/workflow.test.ts` 目前包含 8 项：

1. 普通员工只能看本人单据。
2. 部门负责人只能看和审批本部门单据。
3. 财务、老板、出纳和超级管理员可查看全公司。
4. SQL 查询范围与岗位一致。
5. 付款审批依次经过部门、财务、老板、出纳。
6. 收款由财务确认完成。
7. 期初余额进入账面余额，驳回单据不计入统计。
8. 三天到期与逾期日期判断正确。

当前测试以纯业务逻辑为主，尚未覆盖完整浏览器端到端测试、真实 D1/R2 集成和真实 Webhook 服务。

## 10. 已知限制与下一步建议

### 优先级高

- 将固定初始密码升级为管理员生成的一次性随机密码或邀请链接。
- 为超级管理员增加多因素认证。
- 增加完整 API/D1 集成测试与浏览器端到端测试。
- 增加生产异常监控，并在每日任务失败时主动通知管理员。
- 增加“上传备份文件并恢复”，目前下载后的 JSON 不能直接从网页重新上传。

### 优先级中

- 发票与单据、付款计划之间增加更完整的关联和核销。
- 银行流水增加人工匹配、拆分匹配和撤销对账。
- 数据量增大后增加服务端分页、筛选和报表缓存。
- 对账户、部门、项目、分类增加删除前引用检查。

### 产品边界

当前系统属于公司内部收支流程管理工具，不是完整会计总账系统，暂不包含会计科目、复式记账、凭证、结账、税务申报和法定财务报表。
